# 日志页功能评估：分页 / 开始·暂停·清除·保存 / 墙钟时间

2026-10-17 · 依据：`modbus-core/.../core/model/Types.kt`（`TrafficEvent`）、`core/transport/Transport.kt`（`MonotonicClock`）、`app/application/DefaultSessionManager.kt`、PR-3 分支 WIP `ui/traffic/TrafficViewModel.kt`。

## 结论先说
**不需要老板放开 modbus-core。** 四项需求（分页、开始/暂停/清除/保存、“点开始才记录”、每帧墙钟时间）都能在 ui + application 层完成；core 和协议不动。仅有的几处局限见 §6，都不阻塞。

## 1. TrafficEvent 带不带墙钟时间？
- `TrafficEvent(monotonicNs, direction, bytes, kind)`：**没有墙钟时间，也没有 id / pairedId**。
- `monotonicNs` 来自 `MonotonicClock.nowNs()`，默认实现 = `System.nanoTime()`（`Transport.kt:11`；两个引擎都用 `clock.nowNs()` 构造事件，`MasterEngine.kt:187`、`SlaveEngine.kt:278`）。
- 所以**墙钟时间可以在 app 层精确换算**，不用改 core：`wallMs = System.currentTimeMillis() − (System.nanoTime() − event.monotonicNs) / 1e6`。
- 为什么要在**采集的那一刻**换算并存下来：`System.nanoTime()` 是单调时钟，设备深度休眠时不走，墙钟照走；事后很久再换算会差一段休眠时间。app 层采集器（见 §2）在收到事件时立刻换算，延迟只有协程调度那几毫秒。
- 注意：现在日志 VM 只在页面打开时收集，`SharedFlow` 的 `replay = 1000` 会把页面打开前的事件一次性重放，那些事件如果在此刻换算，误差 = 它们的年龄（休眠时更大）。→ 采集器要做成**应用级**（不依赖页面），会话一开始就在收，才能给每一帧一个可信的时间。
- 若老板以后希望时间戳由 core 直接给（更干净），需要给 `TrafficEvent` 加 `wallClockMs` 字段（core 改动，很小）；**当前方案不依赖它**。

## 2. “默认不记录，点开始才捕获” 要不要动 core？
**不需要。** core 的引擎无条件产生事件并发到 `DefaultSessionManager._traffic`（`MutableSharedFlow(replay = 1000, DROP_OLDEST)`，在 **application 层**，不是 core）。“是否记录”是**采集器**的事：
- 新增应用级单例 `application/TrafficRecorder`（与 `SessionManager` 同级，Activity 重建/切页不丢）：
  - `state: IDLE(默认) → RECORDING ⇄ PAUSED`；
  - 点“开始”：记下 `startNs = System.nanoTime()`，开始收集 `session.traffic`，**丢弃 `monotonicNs < startNs` 的事件**（挡住 replay 重放的旧帧，满足“点开始后才捕获”）；
  - “暂停”：停止收集新帧（取消收集协程），**保留已有**；再点“开始/继续”恢复，暂停期间的帧**不补**；
  - “清除”：清空已记录列表（不改变 记录/暂停 状态）；
  - 会话换代（`SessionState.Running.epoch` 变化）：保留已记录帧，在列表里插一条分隔“— 新会话 —”（不自动清，也不自动停；是否换会话时停止记录可以做成设置，默认不停）。
- 容量：内存上限（默认 20,000 帧或约 8 MB，取先到者）；满了**停止记录并提示**（而不是悄悄丢旧帧——抓包场景不能无声丢数据）。是否改成环形覆盖旧帧，由老板决定（默认：满了停并提示）。
- 日志页不再自己收集 session.traffic，改读 recorder 的列表；页面还在，但“未开始”时显示空态“点击开始记录通信”（不是显示重放的旧帧）。
- 副作用：现在“打开日志页就看到最近 1000 帧”的行为会变成“看不到，除非点过开始”。这是老板明确要的新行为，但与稿面（b1-6/b6-1 默认就有帧）不一致 → 记为与稿面的差异，写进 PR 描述。

## 3. 分页方式
- 现状：`LazyColumn` + 最近 1000 条上限（已虚拟化）。
- 分页：**每页 100 条**（设置里可选 50/100/200，默认 100；不让用户输入任意数以免卡），底栏 `‹ 上一页  第 3 / 27 页  下一页 ›` + 点页码弹“跳转到页”。
- “跟随最新”：记录中且在最后一页时，自动停在最后一页并滚到底；用户翻到旧页 = 暂停跟随（沿用现有“暂停滚动”按钮语义），不影响记录。
- 过滤（TX/RX/异常…）作用在**整个记录集**之后再分页，页数随过滤变化。
- 选中帧、详情（横屏右栏）按 `seq` 认，不按页内下标（沿用现有设计，翻页不丢选中）。
- 测试：页数计算（空/整除/余数）、翻页边界、过滤后页数、跟随最新、记录中追加不抖动。

## 4. 开始 / 暂停 / 清除 / 保存 的界面
- 日志页顶部（会话条之下）加一条工具栏：`● 开始记录`（未开始，琥珀）/ `⏸ 暂停`（记录中）/ `▶ 继续`（已暂停）；右侧 `清除` `保存`；状态小字“记录中 · 128 帧 · 00:42”。横屏放在右栏顶部。触控 ≥ 48dp。
- 清除：有数据时弹确认（防误触，“清除后不能恢复”）；无数据时按钮禁用。
- 保存：见 §5；无数据时禁用。
- 与现有“暂停滚动 / 过滤 chip”并存：**暂停记录 ≠ 暂停滚动**，文案和图标要区分（暂停记录 = 停止捕获；暂停滚动 = 列表不再自动跟随）。建议把现有“暂停滚动”改名“锁定滚动”。

## 5. 保存（导出）实现
- 格式：CSV（`序号,时间,方向,类型,长度,HEX,CRC,摘要`；UTF-8 带 BOM 以便 Excel 打开中文）和 TXT（每帧一行：`HH:mm:ss.SSS TX 01 03 00 00 00 02 C4 0B  读保持寄存器…`）。**两种都带墙钟时间 `HH:mm:ss.SSS`**，CSV 另带完整 `yyyy-MM-dd HH:mm:ss.SSS` 一列（跨天可查）。
- 走系统界面，不申请存储权限：
  - **保存到文件**：`ActivityResultContracts.CreateDocument(mime)`（SAF，用户选位置/文件名，建议名 `modbus-log-20261017-153042.csv`）；
  - **分享**：先写 `cacheDir/exports/…` 再用 `FileProvider` + `ACTION_SEND`（需要在 manifest 加 `<provider>` 和 `res/xml/file_paths.xml`，是 app 模块改动，不是 core）。
  - 保存按钮弹一个小面板：`保存到文件… / 分享…` 两项 + 格式选择 CSV/TXT。
- **隐私提示**（保存/分享前必弹，每次）：“日志包含设备地址、寄存器数据和通信内容，可能涉及现场隐私或敏感信息。文件只保存在你选择的位置/分享给你选择的应用，本应用不会上传。”按钮：取消 / 继续。
- 大文件：流式写（逐帧写入 `OutputStream`），在 `Dispatchers.IO`，上限 20,000 帧时 < 1 秒；不在主线程拼大字符串。
- 测试：导出文本格式（行数、时间格式 `HH:mm:ss.SSS`、CSV 转义、BOM）纯 JVM；隐私面板出现（Robolectric UI 测试）；**真实 SAF/分享：需要真机，未验证**。

## 6. 局限与风险（都不阻塞，不需要 core）
1. 时间戳精度：采集器收到事件到换算墙钟之间有协程调度延迟（毫秒级）；不是“线上发生的精确时刻”（那需要 core 的 `wallClockMs`）。
2. 设备调系统时间：墙钟随之跳变，已记录的帧不会改（记录的是当时的值）。
3. 应用在后台被系统杀掉：记录丢失（内存里）。要不丢需要落盘（可后做，复杂度中）。
4. `session.traffic` 的 `DROP_OLDEST` 缓冲：采集器协程来不及消费时会丢帧（极端高速）；目前一帧一次回调，10 Hz 级别没风险，**高速压力未实测**。
5. 摘要文本（“读保持寄存器…”）仍是 ui 层过渡实现（`FrameDescriber` 在 core，受限）；不影响本项。
6. `TrafficEvent` 没有 id/pairedId：配对帧继续用 ui 层的启发式（只在 TX→RX 紧邻时配对，不乱猜）；不影响本项。
