# Modbus Mobile — 远期能力候选路线（非首版规格）

日期：2026-10-16。**这是候选立项清单，不是 M0–M6 开发任务，也不是首版完成条件。** 每项启动前须提交独立 RFC，至少包含需求验证、协议标准来源、库许可、方案、排期、风险、测试矩阵和退出标准。除经过独立立项，不得合并开发。

## 唯一首版：M0–M6（V5.1）

见 [spec.md](spec.md) 第 8–9 章；首版限定 USB Modbus RTU 主站与从站、寄存器、基础曲线、日志和离线文件交换。V5.1 的帧扫描、服务启动、广播原子性和配置快照修订已收纳在首版规格，**不意味着 E1–E6 提前立项**。

## 后续候选 E1–E6

| 候选 | 目标 | 明确前置门槛 | 不隐含的功能 |
|---|---|---|---|
| E1 数据内核强化 | 跨项目点位对象、质量/时间模型、更丰富解码与样本缓存 | M0–M6 可用，现有模型瓶颈得到度量 | 不因此启动组态与控制 |
| E2 串行协议扩展 | Modbus ASCII、DL/T645 按独立 RFC 做主站；从站仿真另评估 | 获取适用正式标准，明确 DI 及安全子集；独立交叉测试 | 不承诺“所有协议主从都兼容” |
| E3 局域网扩展 | Modbus TCP Client/Server；S7 主站仅定义支持的握手与数据读写子集 | 用户场景确认、网络权限核实、库及许可决定；主动连接/被动监听互测 | 不保证完整 PLC 仿真；不默认开放公网 |
| E4 本地监控 | 组态、历史查询、阈值告警与画面编辑 | E1 数据语义稳定；UI/功耗/长期存储测试 | 不强制增加设备输出控制 |
| E5 可视化流程与 Lua | 流程图、算子、可选 PID、受限脚本 | 威胁模型、脚本执行预算、循环图验证、输出冲突策略 | 不预设必须兼容任何商业软件脚本 |
| E6 完整回归 | 已立项扩展能力的集成验收 | 实际启用项的测试矩阵与支持设备清单 | E6 不把未立项 E2/E3/E5 变成必做 |

### 需要独立决定的技术事项

- **Lua**：LuaJ（纯 JVM）或经 NDK 引入 Lua C VM 不提前锁定。需分别论证：脚本指令/CPU 预算、内存上限、死循环中止、宿主 API 白名单、隔离线程/进程、许可证和 Android 兼容性。没有可验证预算实现前禁止脚本控制真实设备输出。
- **S7**：比较 Moka7、Snap7 或自己实现的可行性、许可证、维护状态和支持子集，必须有独立协议向量、真实 PLC 联调，不能把客户端连接成功等同于完整 S7 协议支持。
- **DL/T645**：应先取得正式标准及预期电表的 DI 表和相应修订信息；这一条件未满足时不得对外承诺合规或完整兼容。
- **Android 局域网**：Android 17/API 37+ 且 target SDK 为 37 及以上时，局域网 socket 访问需按官方文档声明并请求 `ACCESS_LOCAL_NETWORK`（可能存在系统选择器例外）；当前 USB 首版无需任何此类权限。官方：https://developer.android.com/privacy-and-security/local-network-permission
- **协议全覆盖**：不能把“共六种协议，每一种均同时有完整主/从站能力”视为默认目标；要逐项定义可实现的服务端仿真范围。
- **商业软件参考**：仅参考通用设计思路，使用公开标准和独立功能需求撰写 RFC。无第三方工程格式导入兼容需求，不复刻其缺陷、UI 资产、私有交互或二进制代码。

## 立项模板（每个 E 项单独填写）

1. 用户场景与不可替代价值。
2. 本阶段包含/排除哪些协议功能、平台 API、页面与数据模型。
3. 依据哪份公开规范与可分发许可的库；版本号与许可检查。
4. 增量架构与边界，已有 M0–M6 是否需要迁移。
5. 技术不确定性、可提前验证的 PoC、性能和电量预算。
6. 单元、互操作、真机、回归矩阵，失败处理和退出条件。
7. 资源排期、依赖、授权审批与回滚方案。
