# 注意事项（Corn Bench 第一期）

本文是合并后仓库的贡献与评审必读。原有两个仓库的规则继续有效，分别见
[docs/modbus/注意事项.md](modbus/注意事项.md) 与 [docs/flashing/README.md](flashing/README.md)；
这里只补 **Corn Bench 合并后新增 / 变化** 的部分。

## 一、分支与合并

1. 第一期只在 `feat/phase1-shell` 上开发；PR #1 是草稿，**合并进 main 必须等老板本人明确确认**，在此之前不合并、不改 draft 状态。
2. 两个源仓库 `Corn-Flashing` / `corn-modbus` 只读：不改、不推、不再从它们同步（历史已完整合入本仓库）。
3. 每完成一个子任务：更新 `board.md` → commit → push；`board.md` 是进度与验证状态的唯一出处。
4. 没跑过的东西写“未验证”，不要用 Robolectric 渲染或单测冒充实机验证。

## 二、模块边界

5. `:app` 是唯一 Android application；两个 feature 是 library，**不得再出现自己的 Activity / Application / 启动图标 / window 主题**。
6. 模式的依赖必须懒加载：只有真正进入某个模式（或系统重启该模式的前台服务）时才创建它的 Room / USB / DataStore。
   外壳与 `ModeGuard` 只允许查询状态，不能顺手把另一个模式的容器建出来。
7. 两个 feature 共用一个 applicationId，所有进程级标识都要带模块名：
   - USB 授权 action：`<包名>.flashing.USB_PERMISSION` / `<包名>.modbus.USB_PERMISSION`
   - SharedPreferences / DataStore：`flashing_ui` / `ui_settings` / 外壳 `bench_ui`
   - 通知 channel、FileProvider authority 同理，不要用裸 `<包名>`。
8. 视觉常量只能来自 `:ui-common` 的语义 token；feature 内保留旧字段名可以，但值必须取自 token，并由比对测试锁定。

## 三、模式切换

9. 切换前必须走 `ModeGuard`：`blockedReason()` 非空就置灰目标卡 + 写原因，不做“强制断开”。
10. `release()` 返回 false（超时 / 任务没结束）时**停在本模式**并提示，不能假装切过去了。
11. 模式切换不重启 Activity；每个模式一个独立 `ViewModelStore`，切走时清掉，避免旧会话状态串到新模式。
12. 插入 USB 设备**不自动切换模式**，只给提示；自动切模式需要重新拍板。

## 四、第一期外观

13. 第一期只开放深色：外壳固定深色；上位机侧 `PHASE1_DARK_ONLY` 把主题归一成 DARK，
    外观页隐藏“主题 / 强调色”两项但**不删代码**，第二期改常量即可恢复。
14. App 字号只允许叠一次（系统倍率 × App 倍率）。`ModbusTheme` 不要再自己 `provides LocalDensity`。
15. TX 色固定青绿 `#4FD1C5`；不要退回原 Modbus 的琥珀 `#F5A524`（与玉米黄几乎分不清）。
16. 系统栏图标深浅由外壳统一设置（`BenchSystemBars()`），任何模式都不要在自己的 Activity 里再设一遍。

## 五、CI 与验证

17. CI 要跑：两个 core 的 test、两个 feature 的 `testDebugUnitTest` + `lintDebug`、`:app` 的 test / lint / Roborazzi / assemble。
    只跑 `:app` 会漏掉两个 feature 的近千个单测。
18. 本机 `tools/rtu_lab` 已挪到 `tools/modbus/rtu_lab`；CI 的缓存路径与脚本路径都要跟着改，否则 `setup-python` 直接失败。
19. 不提交 Roborazzi 录出来的基线 PNG；CI 只作为 artifact 上传。
20. 真机 / 模拟器上的模式切换、USB 授权、前后台切换，没跑过就写“未验证”。
